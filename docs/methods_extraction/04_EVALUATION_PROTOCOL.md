# 04_EVALUATION_PROTOCOL

## 1) Binary pairwise CV protocol
- Pairwise dataset is generated by crossing each sample with each candidate MoA embedding (including augmentations) and setting binary target `Label = 1` for true MoA match, else `0`. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: generate_backbone_df :: `"Label": int(moa == true_moa)`]
- Split strategy for repeated CV is **compound-level stratified K-fold** built from one MoA label per compound. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: _cmp_label_map/build_or_load_compound_folds :: `StratifiedKFold`]
- Repeats are controlled by `cv_iterations`; each iteration uses random state `base_seed + 1000*iter`. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: build_or_load_compound_folds :: `random_state=int(base_seed + 1000*it)`]
- Within each fold, model replicas are run with seeds `base_seed + rep_idx` for `seed_splits` repeats. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model :: `for rep_idx in range(seed_splits)`]
- Actual saved runs in this repo for major figure experiments show `cv_splits=5`, `cv_iterations=5`, `seed_splits=1` in `meta.json`. [ref: code_repository/predictions/Feature_augmentation_experiment/binary/semantic_BioBERT_tabm_Text_Embedding+Proteomics+ECFP+CellPaint+MIC+GC/meta.json :: keys :: `cv_splits`, `cv_iterations`, `seed_splits`]

## 2) LOO / LOSO protocols
- LOO (`binary_pairwise_LOO`): one held-out compound per fold, all other compounds in train. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_LOO :: `for fold_idx, test_cmp in enumerate(unique_compounds)`]
- LOSO (`binary_pairwise_LOSO`): one held-out MoA class per fold; train compounds are classes `!= heldout`. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: make_class_loso_splits :: `heldout_class`]
- LOSO ablation in runner sets `drop_heldout_candidate_in_train=True` for stricter candidate exclusion from train rows. [ref: code_repository/scripts/Data_generation/LOO_eval_script.py :: call evaluate_model_LOSO :: `drop_heldout_candidate_in_train=True`]
- Actual saved ablation runs use `seed_repeats=5`, `base_seed=42`, `mc_passes=0`. [ref: code_repository/predictions/Uncertainty_experiment_semantic/binary_loso_ablation/semantic_BioBERT_tabm_Text_Embedding+Proteomics+ECFP+CellPaint+MIC+GC/meta.json :: keys :: `seed_repeats`, `base_seed`, `mc_passes`]

## 3) Multiclass evaluation from pairwise scores
- Pairwise `Score` is pivoted to `SampleID x CandidateMoA` and aggregated with `mean` over augmentations before argmax class prediction. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_multiclass_pairwise :: `pivot_table(... aggfunc="mean")`]
- Top-k metric uses sorted class scores with default `topk=3`. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_multiclass_pairwise :: `topk: int = 3`]
- No-text multiclass protocol uses sample-level features and `LabelEncoder` integer targets with same compound-level fold manifest mechanism. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_multiclass_samples :: `task": "no_text_multiclass"`]

## 4) Leakage prevention checks (verified only)
- Folding is performed at compound level via `groups` masks (`CompoundID`), not row-level random split. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model :: `tr_mask = groups_ser.astype(str).isin(...)`]
- `StandardScaler` is fit on train rows only and then applied to test rows per fold. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model :: `fit_transform` then `transform`]
- Fold manifest validation checks same compounds and labels before reuse. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: build_or_load_compound_folds :: `_deserialize` checks `compounds` and `labels`]

## 5) Metrics and definitions
- Binary metrics per run: `f1_score(y_te, y_pred)`, `roc_auc_score(y_te, proba)`, `average_precision_score(y_te, proba)`; aggregate by mean (`avg_f1`, `avg_roc_auc`, `avg_pr_auc`). [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model :: metric calls]
- Multiclass metrics (pairwise->multiclass and no-text):
  - `top1_acc`: mean exact match.
  - `topk_acc`: hit if true class in top-k scores.
  - `macro_f1`, `micro_f1` over present classes.
  - one-vs-rest macro ROC-AUC and AP (`avg_macro_roc_auc_ovr`, `avg_macro_ap_ovr`). [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_multiclass_pairwise :: `macro_f1`, `micro_f1`, OVR loops]
- Prediction threshold for binary class label conversion is `0.5`. [ref: code_repository/scripts/Data_generation/Codebase/eval_utils.py :: evaluate_model_LOO :: `y_pred = (proba >= 0.5).astype(int)`]
